# 个人空间退出基线与执行计划

本文记录 2026-09-29 的产品基线和跨仓库执行顺序。线上新账户默认关闭个人空间已经是当前生产事实；这不等于历史个人数据已经删除，也不等于最终退出项目已经完成。服务端接口合同以 [aperag-enterprise 的个人空间可选化服务端合同](https://github.com/apecloud/aperag-enterprise/blob/main/docs/engineering-process/2026-09-26-personal-workspace-contract.md) 为准；统一的可选空间、空列表、权限前置和剩余工作以 [个人空间可选合同](2026-09-29-personal-workspace-optional-contract.md) 为准。本文把“当前兼容”和“最终退出”拆成可验证的工作包，不能把局部代码或测试写成已经发布。

## 产品基线

线上新账户已经默认关闭个人空间。个人空间在过渡期内仍可能出现在历史账户中，也可能存在但没有知识库；个人数据迁移完成后，个人空间可以完全不再返回。长期没有个人空间是正常账户形态，登录、组织访问、Agent、CLI 和 Desktop 都必须在这种形态下继续工作。

个人空间的存在性由服务端的 workspace presence resolver 和 `/api/v2/me/workspaces` 响应决定。客户端不能根据用户 ID、`personal:<user_id>` 前缀、旧资格字段或“知识库列表为空”推断个人空间。`items: []` 表示身份已经建立但当前没有可用工作空间；缺少 `items`、`null`、非数组、空 ID、空状态或未知类型则是 `invalid_response`，不能被当成空列表。

这条基线把三个事实分开处理：个人空间存在、个人空间存在但为空、个人空间不存在。没有空间不会使 OAuth 或 API Key 身份失效，但所有需要数据命名空间的操作都必须在限流、扣额度、写数据库、启动后台任务和工具执行之前返回 `workspace_required`。账户级状态、登录刷新和凭据撤销可以继续使用。

## 对系统设计的影响

### 服务端

- `/api/v2/me/workspaces` 是唯一的工作空间发现来源；响应中的 canonical `id`、`type` 和 `status` 是客户端可保存和传递的唯一标识。
- presence、成员关系、资源权限和 API Key 绑定必须在每个 workspace-aware 入口重新校验。缓存、站点管理员身份和旧 `personal_workspace_enabled` 字段都不能扩大普通请求范围。
- 个人初始化、默认 API Key、默认 quota、默认 Bot 和恢复路径都只能在 resolver 确认个人命名空间仍然可用时执行。缺少个人空间不能触发重新创建。
- 个人迁移、导出、删除、回滚和旧别名清理都是独立的数据项目；普通登录、刷新、客户端升级和组织 onboarding 不得隐式触发这些动作。

### CLI

- `workspace list` 在空集合时返回成功的空数组，`workspace current` 返回 `current: null`；数据命令返回稳定的 `workspace_required`。
- `workspace use`、`--all-workspaces`、API Key 连接恢复和能力诊断只使用服务端实际返回的 active workspace，不能合成个人空间。
- 未绑定组织的旧 API Key 只有在服务端仍返回个人 workspace 时才可作为数据连接；个人空间关闭或迁移完成后，账户级查询仍可用，数据请求必须给出 `workspace_required`。
- CLI 错误要区分认证失败、空间缺失、空间过期和协议错误，Agent 才能决定刷新、选择组织或停止重试。

### Desktop

- 登录成功不再承诺一定有个人空间。选择器、知识库、模型、Agent、Chat 和 Turn 页面都需要有空状态、刷新和加入组织的恢复动作。
- Renderer 只展示 CLI 和服务端结果，不复制授权逻辑，不从本地用户信息拼接 workspace ID，不因为列表为空初始化个人资源。
- 打包的 CLI 版本必须与 UI 合同一起验收；空空间、失效选择和组织切换都要在打包应用中验证。

## 当前执行状态

服务端和 CLI 已经把“个人空间存在、存在但为空、完全不存在”作为不同状态处理；Desktop 侧已同步登录、工作空间、API Key 和空状态合同。Desktop 当前只消费 CLI/服务端返回的 canonical workspace，不会从用户 ID 或旧 flag 合成个人空间。服务端 Chat 附件路径也已保证隐藏 Collection 继承父 Bot 的 namespace，并在历史失配时 fail closed；对应定向测试当前为 45 passed。文档和定向测试可以证明合同一致，不能代表打包应用已经完成六态验收或线上版本已经更新。

后续 Desktop 工作只保留必要的图形化收口：在真实打包产物中验证 `workspace list/current/use`、历史选择失效、无空间登录、多组织选择、个人空间关闭后的恢复动作，以及内置 CLI 版本。服务端资源审计、个人数据迁移和 Widget 组织授权仍以服务端仓库的执行计划为准，不能在 Desktop 内复制第二套授权逻辑。

## 六种账户状态

所有 workspace-aware 资源都要覆盖以下状态。每个状态还要叠加 OAuth、组织 API Key、历史未绑定 API Key、组织成员撤销和当前空间失效等凭据变化。

| 状态 | 工作空间响应 | 必须证明的行为 |
| --- | --- | --- |
| 历史个人空间有数据 | 返回 `type=personal`，可同时有组织项 | 可以读取真实个人数据；组织请求不会越界 |
| 历史个人空间为空 | 返回个人项但没有知识库 | 空知识库与无空间区分，不能自动删除个人项 |
| 新账户默认关闭个人空间 | 组织项或空数组 | 登录和账户级状态成功，不初始化个人资源 |
| 个人数据迁移完成 | 不返回个人项 | 清理旧选择；旧 flag 不恢复个人资源 |
| 多组织账户 | 多个 active 组织项，可选个人项 | 无历史选择时要求明确选择；聚合保留来源和部分失败 |
| 登录后无任何空间 | `items: []` | 发现命令成功；数据命令在副作用前返回 `workspace_required` |

## 剩余工作包

工作按风险和依赖顺序推进，不能以某一个路由的绿色测试替代整条合同。

1. **服务端入口审计**：逐条审计 Document、知识库导入和导出、Quota、Model、API Key、Bot、Chat、Turn、证据、附件、Tagging、分享、Marketplace、MCP、Computer、历史恢复和初始化路径。记录真实入口、presence/member/resource gate、可能的副作用和现有测试。
2. **服务端合同测试**：为每个入口补齐六种状态，重点检查错误码、跨组织拒绝、旧选择失效，以及失败前没有额度扣减、幂等收据、后台任务、outbox 或工具调用。测试要从 HTTP/MCP 入口开始，不能只测内部 helper。
3. **CLI 收口**：完成登录/刷新、空间列表和选择、失效选择清理、未知类型拒绝、组织 API Key、账户级 Key、模型代理、通用 `api` 和 `--all-workspaces` 的真实二进制验收；统一 JSON、JSONL、退出码和部分失败输出。
4. **Desktop 收口**：在打包应用中验收空列表、唯一组织、多组织、空间失效、个人配额/默认 Agent 不出现、CLI 版本一致和恢复动作；UI 不新增第二套业务客户端。
5. **Widget 决策**：在个人空间最终退出前，为组织 Agent 定义 Widget 的授权、公开访问和运行时空间边界；如果不继续支持组织 Widget，先完成下线、迁移和已发布实例处置方案。
6. **个人数据迁移项目**：单独完成数据盘点、导出、备份、迁移、删除、回滚和执行收据，确认旧 `personal:<user_id>` 别名和恢复入口的清理范围。删除前必须有演练、回滚窗口和人工验收。
7. **分环境发布验收**：先在 staging 取得六态的 `/api/v2/me`、`/api/v2/me/workspaces`、知识库、模型、API Key、MCP、CLI 和 Desktop 收据，再安排生产发布。缺少某种真实账户状态时要明确记录“未覆盖”，不能修改真实用户数据凑矩阵。

## 完成标准

当前兼容项目完成的条件是：没有个人空间的账户可以正常登录、刷新、查看账户状态和组织；所有需要空间的操作在真实副作用前返回稳定的 `workspace_required`；个人空间存在时仍可按服务端返回的 canonical ID 使用；客户端永远不合成不存在的个人空间；组织和个人权限不会相互泄漏；staging 和目标生产都有可复查的六态验收收据。

个人空间最终删除的条件另行定义：迁移和导出收据完整、备份可恢复、回滚演练通过、Widget 和旧 alias 已处置、客户端与服务端已停止创建个人资源，并取得数据删除的人工授权。兼容项目完成不等于允许立即删除个人数据。

## 不解决什么

本文不决定个人数据保留期限、删除日期、商业迁移政策或 Widget 最终产品形态，也不授权任何生产数据迁移和删除。它只固定当前接口和客户端在个人空间逐步退出期间必须遵守的行为，以及后续实现和验收的顺序。
