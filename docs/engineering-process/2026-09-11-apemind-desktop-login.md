# ApeMind Desktop 账户连接与工作空间

本文定义 Desktop 如何复用 ApeMind 的 API Key、身份与组织接口，验证连接并调用工作空间内的业务能力。

## 接口与权限

所有请求使用 `/api/v2`，由 Host 携带 `Authorization: Bearer <key>`。沿用服务端的密钥有效期、停用状态和用户状态检查。

| 需求 | 现有接口 | 使用方式 |
| --- | --- | --- |
| 验证 Key、获取用户和绑定空间 | GET /api/v2/auth/user | 检查 bound_org_id；缺少字段的旧服务器不接入 |
| 获取绑定组织名称和状态 | GET /api/v2/organizations/{id} | 仅查询 Key 绑定的组织；要求 active 状态和有效成员投影 |
| 读取知识库 | GET /api/v2/collections | 由服务器按 Key 解析空间；include_subscribed=false，最多展示 20 项 |

不新增 `/desktop/*` 接口，不新增组织请求头，不用客户端组织选择覆盖 Key 的绑定范围。用户所属组织列表不能当成当前 Key 的操作授权列表。个人 Key 对应个人空间；组织 Key 对应它绑定的一个组织。组织角色权限仅供展示，实际操作同时受到 Key 范围限制。

## 用户流程与 UI

设置中的 ApeMind 页面包含连接表单和已连接工作空间。用户填写 HTTPS 服务站点和 Key，提交后清空输入值。验证成功后保存连接并显示账户、服务地址、绑定空间、角色、组织权限和上次验证时间。失效、服务异常或存储失败都返回明确失败，不展示成功。

切换工作空间需要先连接它对应的 Key。每次切换重新验证目标 Key；失败保留原连接。移除连接只清除此设备记录，不撤销服务端 Key，不自动激活其他身份。知识库按钮用当前 Key 发起实际 API 请求，先重验账户与工作空间，响应只投影知识库 id 和 title。

请求期间禁用重复操作；请求串行，防止慢验证在退出后恢复连接。页面卸载不再更新状态，不使用轮询。保存的快照不代表实时授权，页面明确展示验证时间。

## 插件结构

Host 的 ApeMindClient 封装固定的三个读接口、HTTPS 站点校验、15 秒请求超时、禁止重定向和脱敏错误。AccountService 持有账户状态操作，验证完成后才写入存储。AuthorizationController 发布 `remote.apemindAuth`。Renderer 只接收公开投影；Key 仅在用户输入及提交时短暂存在，Host 不向 Renderer 回传已保存密钥。

Remote 提供 state、connect、select、disconnect、collections。不存在伪浏览器登录、授权码占位或手填组织 ID。未来业务工具应通过 Host 获取并校验当前连接，不能从 UI 读取密钥。

## 存储

沿用 dsh 的 ctx.credentials，在 apemind/connections grant record 中保存版本化连接集合和当前选择。Key 与账户/组织绑定，连接标识由服务站点、用户 ID、组织 ID 计算。同一身份空间的新 Key 替换旧连接；不同空间分别保存。

锁定上游的 credentials-local 使用权限 0600 的 .credentials.yaml 文件与跨进程文件锁，并非 OS 钥匙串，也不是加密存储。密钥不可写入日志、URL、错误或公开账户快照。不要把 DSH_HOME 凭据文件提交到版本库。历史 apemind/account 占位记录不会被当作已验证连接自动导入。

## 验证边界

行为测试覆盖真实客户端和账户服务代码：有效和无效 Key、HTTP/网络失败、错误脱敏、组织状态和成员缺失、旧版响应、按对应 Key 切换、读知识库、状态恢复、退出、并发和存储失败。这些测试使用服务端字段结构的模拟 HTTP 响应，不能替代部署环境联调。

完整验收还需要上游全量构建、打包后的插件/Remote 加载、真实测试 Key 的身份及知识库请求、跨组织拒绝和 UI 检查。只有完成这些步骤才能称为桌面功能验收通过。服务端代码如无缺口无需为桌面连接额外发布；仍须核验目标环境已有接口的部署与行为。

## 后续范围

浏览器登录、自动签发组织 Key、系统钥匙串存储、跨组织并行任务和修改型业务工具单独设计。不能用一把受限 Key 默认换取其他组织的操作权限。
